El badge de cada banco indica hasta qué capa está configurado su canal móvil. Van en escalera: cada nivel agrega algo sobre el anterior. Es una guía de "cuánto has configurado", no una garantía — para eso están los ejemplos guardados, que corren el flujo real y dan ✅/❌.

  • Móvil off El canal móvil está deshabilitado: el banco no se escucha por teléfono.
  • Solo origen Sabe de dónde viene la notificación (paquetes de app / patrones de remitente o contenido), pero aún no extrae datos ni resuelve cuenta.
  • Extrae datos Tiene reglas de extracción (parseRules): saca monto, dirección, referencia, cuenta, etc. del mensaje. Todavía no garantiza a qué cuenta YEP pertenece.
  • Resuelve cuenta Extrae datos y tiene política de resolución de cuenta: puede asignar el evento a una cuenta YEP concreta. Este es el estándar para producción.

Para subir de nivel: agrega parseRules (usa "Regenerar parser con IA" a partir de tus ejemplos) para llegar a Extrae datos, y define una estrategia de resolución para llegar a Resuelve cuenta.

Entendido

Cuando llega una notificación transaccional, el backend debe decidir a cuál de las cuentas del notificador corresponde. La estrategia define cómo:

Sin política (por defecto)
Sufijo/últimos dígitos si el mensaje trae cuenta; si no, por unicidad. Es el comportamiento histórico.
Una sola cuenta por notificador
El banco solo permite una cuenta por notificador (Nequi, billeteras). Resuelve por esa única cuenta. Se combina con máx. cuentas por notificador = 1 para impedir asociar más.
Una cuenta del banco → por unicidad
Si hay una sola cuenta de ese banco en el notificador, resuelve a ella; si hay varias, exige señal (cuenta/sufijo).
Solo por número de cuenta completo
Solo resuelve si el mensaje trae el número completo y coincide exactamente. Sin fallback por unicidad.
Por sufijo / últimos dígitos
Resuelve si los últimos dígitos del mensaje coinciden con una única cuenta (mín. configurable). Sin fallback por unicidad.
Sufijo si viene; si no, por unicidad
Intenta por sufijo/cuenta; si el mensaje no trae cuenta y hay una sola candidata, resuelve por unicidad. Útil para bancos que a veces incluyen dígitos y a veces no (p. ej. Bancolombia).
Exige coincidencia dinámica (sufijo obligatorio)
Exige que el mensaje traiga una señal de cuenta que coincida; nunca resuelve solo por unicidad. Para alto riesgo de falsos positivos o apps compartidas.

Opciones adicionales:

  • Mínimo de dígitos para sufijoCuántos dígitos finales deben coincidir para aceptar un match por sufijo (por defecto 4).
  • Máx. cuentas por notificadorLímite de cuentas de este banco que se pueden asociar a un notificador (p. ej. Nequi = 1). Se valida al crear/editar el notificador.
  • Exigir cuenta resueltaSi está activo y no se puede resolver la cuenta, el evento NO se enlaza automáticamente: queda en needs_review para revisión humana.
